## 説明の濃淡（最優先の方針）

**全部を事細かに説明しない。重要な部分を選び、わかりやすさ優先で、図（イラスト）を使って説明する。**
（2026-10-05 本人の指示）

- 論文の全節・全図を均等に扱わない。発表の芯（問題設定・アルゴリズムの核心・主要な結果）に枚数を使い、
  それ以外（関連研究の列挙・細かい実験条件・証明の細部・付録の食い違い）は 1 枚にまとめるかノートに回す
- 芯の部分は文章より図で見せる（プレイヤー・腕・衝突の図、小さな例の動作、比較の図）
- 1 枚に表を 2 つ以上置かない。数値の羅列は、言いたい 1〜2 個の数を大きく見せる図に置き換える
- 細部（式の導出、条件の全列挙、原文と図の食い違いなど）は質問対策としてノートの【口頭補足】に書く

## 本人のフィードバックで決まった書き方（2026-10-12）

- **何でも表にしない。** 数値を並べた表を多用すると、余裕のない圧迫されたスライドになる。表は「同じ項目を複数の対象で比べる」
  ときだけ（1 枚に 1 つ、4 行程度まで）。主張の一覧・分類・根拠の整理は、色つき見出し＋箇条書き（`points()`）、番号つきの項目、図にする（箱で囲まない。下の 4 番）。
  数値は言いたい 1〜2 個だけを図や本文に出し、残りはノートに書く
- **リード文はそのページ全体の要約を 1 文で書く。** 2 文にしない。作った後に全ページのリードを見直す
- **図の見出しを塗りつぶさない。** 図の上の見出しは太字の文字だけ（紺地に白抜きの帯にしない）
- **文字を小さくしない。** 本文は 18〜20pt。擬似コードも 18pt（入らなければ行を減らす。14pt にしない）
- **枚数は 90 分で 40 枚前後。** 節の現在地を示す Flow のページは、3 段程度の小さな部には入れない
- **具体例の表・時刻ごとの数値の表は基本的に入れない。** 定義のページは定義だけを説明する。例を見せるなら図かグラフで
- **原論文に図と説明があるものは、自作の例より原論文の図と説明を使う**
- **論文ゼミで自分の論文を指すときは "Ours" と書かない。** "Ours" は発表する論文の手法に聞こえるので、`Izumi et al. (2026)` と書く
- **MP-MAB の設定の説明は、論文ゼミ_泉0421 の説明スライドを複製して使う**（3 枚目 Review、6 枚目 Setup、9 枚目 Regret Definition。
  記号は発表する論文に合わせて差し替える）
- **査読を通っていない論文（arXiv のみ）を扱うときは、導入に「どこまで信頼できるか」のページを入れる。**
  掲載状況・証明の有無・引用数・著者の実績・再現性を、一次情報（arXiv、著者の所属ページ、Semantic Scholar など）で確かめて書く
- **未解決とされている点は、なぜ難しいのかを自分で考えて 1 枚にまとめる**（原論文に理由がなければ「私の考察」と明記する）
- **ノートの【口頭補足】は、発表で実際に話す価値があるものだけ。** 「図は○○と同じ」「再現用スクリプトは…」のような
  作業メモは書かない。補足がなければ【口頭補足】自体を付けない

## Claude が作るスライドの悪い癖（必ず避ける）

本人に指摘・修正されたもの。生成のたびに `lint.py` と目視で確かめる。

1. **2カラムが多すぎる。** 本人の本文は **1カラムが基本**。2カラムにするのは
   「左に図、右にその規則（擬似コード箱・説明の箱）」のように、左右が**同じ物を別の形で**
   見せるときだけ。箇条書きを左右に割るのは禁止。
2. **謎の余白。** 本人の資料は本文が **6.8in 前後（ページ番号の直上）まで**届き、左右は
   0.54〜12.66in を使い切る。中央に小さな図を浮かべない。図は大きく置く。
   下が空いたら、図を大きくする・例を足す・次のページと統合する、のどれかで埋める。
3. **1枚あたりの情報が少ない。** 本人の本文は1枚に **250〜300字＋数式＋図形10〜15個**。
   リード文と箇条書き3行だけのページは作らない。「定義→数式→記号の説明→例」まで1枚で言う。

4. **何かあるごとに箇条書きを四角い箱で囲む。**（2026-10-15 本人の修正。`assets/reference/スライドデザイン変更点まとめ.pptx` の 5・6 枚目）
   - 箇条書きは**箱で囲まない**。色つきの見出し（20pt 太字、赤 `red`＝注意・課題、緑 `green`＝肯定・根拠）の下に、
     文字だけの箇条書きを置く。各項目の要点（先頭の語句）を見出しと同じ色の太字にし、行頭の • も同じ色にする。
     行間 120%、段落の後 12pt（`points(x, y, w, ["**要点**: 説明", ...], color, heading)`）
   - 対比の 2 列（Cautions / Reasons のように見出しの色で分ける）は、この形なら 2 列にしてよい
   - 塗りの箱を使ってよいのは、リード帯、定義・定理のように 1 つのまとまった主張を 1〜2 文で強調するとき、
     比較の図の一部としての小さな箱だけ。**1 枚に 2 個まで。** 年表のカードや説明文を箱に詰めない
   - 「良い場合 / 悪い場合」のように短い結論を 2〜3 個並べるときは、塗りの箱ではなく `fieldset()`
     （白地・色つき 2.25pt の枠、見出しを枠の上辺に載せる。本文 18pt 中央）。変更点まとめの 1・2 枚目
5. **図の意味がおかしい。** 図は「何が起きているか」が配置だけで読めるように描く（2026-10-15 本人の修正。変更点まとめの 3・4 枚目）
   - **南京錠は、腕に固定されたプレイヤーの横（左）に置く。** 腕の上に置かない（腕のアイコンが隠れ、誰が固定なのか読めない）。
     大きさは 0.56×0.64 前後（`lock()` の既定値）
   - **衝突の爆発図形は腕のアイコンに重ねない。** 矢印が腕に入る所（腕の下端のすぐ下）に置く
   - **同じ腕を 2 人が引く図では、プレイヤーを離して置き、2 本の矢印を 1 本の腕に集める。**
     並んだ 2 人から平行な矢印を出さない（どの腕を引いたのか読めない）。`collide()` がこの型を描く
   - 描いた後に「この図だけを見て、誰が・どの腕を・どうしたか言えるか」を確かめる。言えない図は直す

## ページの組み方（本文スライド）

```
タイトル（24pt 太字 紺 0D114A、左に紺の縦線＝レイアウトが描く）
リード帯（角丸 D9DBE8、0.54〜12.66in、20pt、ページ全体の要約を1文で言い切る）
本文（20pt、色 1C1F28）  ← 2.4〜2.7in から 6.8in まで
                                          ページ番号（右下、自動）
```

- **リード文は省略しない。** そのページ全体の要約を **1 文** で言い切る（「〜を説明する」で終わらない）。
  ただし Overview・目次・図だけのページ・実験設定のページはリード帯なしでよい。
- **本文の見出し**は 20pt 太字の黒（`Example:` `Definition:` `where:` `Objectives of this Paper:`）。
  段階を示す見出しは緑 `196723` や青 `0070C0` の太字。
- **長い話題は分割**してタイトル末尾に `(1/9)` を付ける（本人はアルゴリズムの動作例を9枚に割った）。
  分割した各ページは同じ図の配置で、変わる所（矢印・赤枠・状態）だけを変える。
- **出典**：引用は本文中に青字 `{blue-n:[Wang+, 2020]}`。図の出典は左下 12pt（`s.source()`）。

ページの型と座標は `references/layouts.md`。迷ったらそこから選ぶ。

## 説明図

**図は PowerPoint の図形と、assets の3つのアイコンで描く。** 画像の貼り付けは
論文の実験図（グラフ）だけ。概念図・動作例を画像で済ませない。

本人が使う図の語彙（詳細と寸法は `references/figures.md`）:

| 説明したいこと | 図 |
|---|---|
| プレイヤーが腕を引く | 上段に腕（`slot`）を横一列、下段にプレイヤー（`player`）、紺 3.5pt の矢印で結ぶ。左に `Arm k (K = 4)` `Player m (M = 3)` `State s_m` の行ラベル |
| 衝突 | 2 人を離して置き、2 本の矢印を同じ腕に集め、腕の下端のすぐ下に爆発図形（`collide()`。腕には重ねない） |
| 占有・固定 | 固定されたプレイヤーの左隣に南京錠（`lock()`、0.56×0.64。腕の上に置かない） |
| アルゴリズムの規則 | 右に灰色細枠の擬似コード箱（`code`）。`if/then/else` は赤の細字、いま効いている行に淡青 `D1E1EA` か黄 `F6EAC3` の帯 |
| 時刻の進行 | 左上に `t = 3` の小箱（`tbox`）と、時刻の帯の上の紺の下向き矢印 |
| 値の変化 | 変わった値を赤枠（`frame`）、表のマスを赤丸（`ring`） |
| 分類・階層 | 角丸の箱（淡い面＋紺の細枠）を紺 1.5pt の矢印でつなぐ木。難易度などは右に縦の矢印 |
| 段階の流れ | ❶❷❸❹ ＋ 小さな三角で縦につなぐ（`steps`）、または山形の帯（`chevrons`）。段階ごとに緑→青 |
| 現在地 | Flow を毎回再掲し、今の段だけ赤、他はグレー |
| 対応関係 | 吹き出し（`callout`）、中かっこ（`brace`）、数式の背面マーカー（`mark`） |

**アルゴリズムは必ず具体例で動かして見せる。** 小さな例（例 `M=2, K=3`）を決め、
時刻ごとに「誰がどの腕を引き、どこで衝突し、どの値がどう変わるか」を1ページずつ描く。
数値は実際に計算した値を使う（手で作らない）。

## 数式

**例外なく PowerPoint の数式モード（OMML）にする。** 画像・普通の文字・Unicode の
並べ書き（`μ_k` を文字で打つ等）は禁止。

- 文中：`$\mu_k$` と書く（`text()` などが数式オブジェクトにする）
- 別行：`s.eq(r"...", y, number="(1)")`。式番号は同じ行の右端に別の箱で置く
- 表のセル・図のラベル・箱の中の記号も `$...$` で書く
- 対応する記法は `scripts/omml.py` の冒頭（`\hat` `\tilde` `\mathbb` `\mathcal` `\underbrace`
  `\max_{}` を含む）。未対応の命令はそのまま文字で出るので、`lint.py` が `\` や `$` の残りを ERROR にする

## ノート（発表原稿）

**ノートも読みやすく組む（2026-10-05 本人の指摘）。** `s.notes()` に次の書き方で渡すと、本人のノートと同じ書式
（11pt、1 行目は太字のタイトル、行頭記号 • の箇条書き）になる。

- 1 行目：タイトルの日本語訳（自動で太字）。2 行目は空行
- 本文（リード文の訳）の後に空行、図や箇条書きの訳は「・」で始める（2 段目は「  - 」）
- 【口頭補足】【図】などの見出しは自動で太字。`**太字**` も使える
- **数式は `$...$` で書く（ノートでも数式モードになる）。** `μ_k` のような文字の並べ書きはしない


- **論文ゼミ・輪講ゼミ**：本文は英語。ノートには**1行目にタイトルの日本語訳、空行、
  本文（リード文・箇条書き・図中の文）の日本語訳**を全ページ書く。本人の形式：

  ```
  復習: マルチプレイヤー多腕バンディット (MPMAB)

  複数のプレイヤーが同一のバンディット問題を解く設定。…
  ```
  口頭で補うことがあれば、その後に `【口頭補足】` を付けて書く。
- **修論発表など日本語スライド**：ノートは話す原稿。

## 使い方

```python
import os, sys; sys.path.insert(0, os.path.expanduser("~/.claude/skills/seminar-slides/scripts"))
from deck import Deck, C

d = Deck()
d.cover(tag="論文ゼミ 発表資料", title="...", authors="Cindy Trinh¹, Richard Combes¹",
        venue="arXiv:2102.10200 (2021)", date="05.10.2026", grade="M2", name="泉 知成",
        affiliations=["¹ CentraleSupélec, France"])
d.toc(["Introduction", "Algorithm", "Experiments"])
d.divider("Algorithm")

s = d.slide("Setup: Regret Definition", lead="**Goal:** minimize the {red:regret}.")
y = s.text(C.L, s.top, C.W, "Let $\\mu_k$ be the mean of arm $k$.")
y = s.eq(r"R(T) = T\sum_{k=1}^{M}\mu_{(k)} - \mathbb{E}\left[\sum_{t=1}^{T}\sum_{m=1}^{M} r_m(t)\right]", y + 0.1, number="(1)")
y = s.bullets(C.L, y + 0.1, C.W, ["$r_m(t)$ : reward of player $m$", "..."])
s.notes("セットアップ: リグレットの定義\n\n目標：リグレットを最小化する。…")
d.save("論文ゼミ_泉MMDD.pptx")
```

文字の記法：`**太字**`、`{red:赤の太字}`、`{red-n:赤の細字}`、`{blue-n:[Wang+, 2020]}`、
`{i:斜体}`、`{u:下線}`、`$数式$`。改行は段落。色の名前は `design-tokens.md`。

主な部品：`text` `bullets` `points` `heading` `label` `clabel` `num` `steps` `eq` `box` `fieldset` `shape` `arrow`

`chevrons` `tbox` `mark` `source` `quote` `notes` `paste`（引数は `deck.py` の docstring）。

- 箇条書きは `points()`（箱で囲まない・色つき見出し・要点を色つき太字・行間 120%）。`bullets()` は見出しのない短い列挙だけ
- 短い結論を並べる囲みは `fieldset()`（白地・色枠・見出しを枠の上辺に）。塗りの `box()` に箇条書きを入れない

積み上げは戻り値の y を使う（高さは見積もり。最後は目視で確かめる）。

- `python scripts/bottoms.py deck.pdf` で各ページの本文の下端を測り、6.80in を超えたページを詰める（左下の出典 12pt は 7.0in から下でよい）。
  `scripts/edges.py` は端の余白（下 6.86〜6.99in・左右）への食い込みを画素で調べる。**見積もりの高さではなく実際の描画で判定する。**
- 箱は `box(..., h=None)` で文字に合わせた高さにする。下まで引き伸ばした箱は、文字の上下に空きができて見苦しい（本人の指摘）。
- **確認は PowerPoint の描画で行う（`render_pp.sh`、AppleScript 経由）。** Keynote の確認画像では
  見えない崩れが PowerPoint で出る（2026-10-05 に確認）：数式は見積もりより幅と高さを取る
  （`t = 1` の小箱が 2 行に割れる、`\arg\max_k` や `\lceil\sqrt{M}\rceil` の行が次の行に重なる、
  幅の狭い別行の式が折り返す）、吹き出しが図の曲線や凡例を隠す。
- `render_pp.sh` は出力先フォルダへのアクセス許可が要る。初回は PowerPoint に「ファイル アクセスを許可」が
  出るので、本人に作業フォルダを選んで許可してもらう（許可がないと保存が無言で失敗するか、止まる）。
  PDF の保存先は `save p in (POSIX file "...") as save as PDF` の形で渡す。
- 本人が開いている他の資料（修論スライドなど）は閉じない・保存しない。`render_pp.sh` は自分が開いた資料だけを
  フルパスで探して閉じる。
- **PowerPoint が開くたびに「修復しますか？」と出るのは、生成ファイルの XML の誤り。** 2026-10-05 の原因は、
  表を包む `<mc:Choice Requires="a14">` で接頭辞 `a14` が宣言されていなかったこと（`Deck.save()` で宣言を足して解決）。
  `check.py` はこの種の誤りを検出しない。修復が出たら、修復版を別名保存して元のファイルと比べる。
- PowerPoint が使えないときだけ `render.sh`（Keynote）。Keynote を終了させるので、本人が Keynote を使っていないか先に確かめる。
  Keynote は表の中の数式を描かないため、`table()` は代替表示（数式を文字にした表）を付けてある。
- 一覧画像を**全ページ**見る。重なり・はみ出し・空きすぎ・図とラベルのずれを直して作り直す。

- 仕上げにフォントを埋め込んだ PDF を作る（PowerPoint の PDF 書き出しは埋め込む。`pdffonts` で emb=yes を確認）。
